# SessionBuddy — Cross-Cutting Review

**Date:** 16 August 2026 · **Scope:** API consistency, RBAC consistency, UI consistency, security, UX
**Method:** five parallel deep-read agents over the full source tree, then three adversarial verification agents that attempted to refute every high-severity claim. Only findings that survived refutation appear below. Corrections applied by the verifiers are marked *(verified: …)*.

---

## Executive summary

The codebase is in better shape than a review of this length suggests. The security fundamentals are strong — PBKDF2 at 600k iterations with a pepper, 256-bit tokens hashed at rest, a correct CSRF triple-check primitive, a genuinely fail-closed scanner protocol, single-use TTL-bound download grants, zero SQL injection across ~200 statements, and effectively zero XSS surface (one `innerHTML` in the whole app, a static string). The idempotency table, the audit-metadata redactor, and the `APP_ENV` fail-closed defaults are all well-built.

The problems cluster in one shape: **good primitives that are applied inconsistently**. A CSRF guard that runs on 100+ routes and is missing on three. A signed cursor codec implemented four times and skipped once. An idempotency contract that's documented, half-implemented, and arbitrarily required. A design system that exists in `product.css` and is re-implemented from scratch on two pages. This is the signature of parallel capability development without a shared enforcement layer — and it's fixable with a handful of shared dependencies plus CI assertions, more than with 60 individual patches.

**Fix first (this week):** items 1–4 below. **Then:** the consistency debt in §2, which is what keeps generating items like 1–4.

## 1. Critical / High — fix first

### 1.1 Cross-tenant read via idempotency replay on speaker-task responses
`src/sessionbuddy/speaker_operations/router.py:826-837` — **CONFIRMED exploitable**

The replay branch of `POST /api/v1/speaker/tasks/{task_id}/response` resolves the task from the **path parameter** with no scoping:

```python
current = row_mapping(
    await db.prepare("SELECT id,state,response_json,version FROM speaker_tasks WHERE id=?1")
    .bind(task_id).first()          # ← no organization_id / event_id / event_speaker_id
)
return SpeakerTaskResponseView(response=json.loads(str(current["response_json"])), ...)
```

The write path 12 lines below (`:838-851`) scopes correctly by `organization_id`, `event_id`, and `event_speaker_id`. Two guards that *should* have caught this both fail:

- `route_key` is the **un-substituted template** `"POST /api/v1/speaker/tasks/{task_id}/response"` (`:809`) — a literal string, identical for every caller.
- `request_fingerprint` hashes `body.model_dump()` only (`:739-741`), and `SpeakerTaskResponseCreate` carries just `answers` + `version` — no path parameter. Contrast `create_event` (`access.py:2684-2690`) and `duplicate_event` (`access.py:1894-1900`), which both fold the scope id into the fingerprint.

**Attack:** complete one of your own tasks with key `K` and body `B`; re-POST to `/api/v1/speaker/tasks/{VICTIM_TASK_ID}/response` with the same `K` and byte-identical `B`. `require_permission` passes (it only proves you're *some* active speaker), the fingerprint matches, and the victim's private questionnaire answers return verbatim in the 200 body — **across organizations**. `response_json` is exposed by no other route.

*Constraint the verifier added:* `task_id` is a UUIDv4, so this needs a known/leaked id rather than enumeration. Organizers receive task ids via `GET /api/v1/admin/events/{id}/onboarding`, so an event editor who also holds a speaker role anywhere is a realistic attacker.

**Fix:** resolve from `replay["response_resource_id"]` (which `complete_idempotency` already persists, `platform/db/commands.py:101-116`) and re-apply the `:838-851` predicate. Add the negative test — none exists.

### 1.2 Login CSRF: magic-link verification sets a session cookie with no origin check
`src/sessionbuddy/platform/auth/access.py:4409` (GET) and `:4975` (POST) — **CONFIRMED**

Neither handler calls `guard_mutation`. The GET variant mutates state directly (`UPDATE authentication_challenges SET consumed_at_ms=…`), and the POST accepts `application/x-www-form-urlencoded` with the token in the query string. The verifier checked the interstitial: `static/auth_link_confirm.js` calls `form.requestSubmit()` on `requestAnimationFrame` — **zero user interaction**, and the form carries no anti-CSRF token. The cookie is `SameSite=Lax`, which governs *sending*, not *storing*, so a cross-site top-level navigation's `Set-Cookie` is accepted.

**Attack:** attacker requests a magic link for their own address, hosts `<form method=POST action="https://app/auth/verify?token=THEIR_TOKEN" target=_top>` with an auto-submit. Any victim who loads it is silently signed into the attacker's account — every proposal drafted, slide deck uploaded, or profile detail entered from then on lands in an account the attacker reads at leisure. A plain `<img src=".../api/v1/auth/verify?token=...">` works too.

**Fix:** require an exact allow-listed `Origin` on `POST /auth/verify`; make `GET /api/v1/auth/verify` non-mutating (it also declares a JSON request body in the published OpenAPI, §3.5).

### 1.3 The deployed `development` environment has malware scanning switched off
`wrangler.jsonc:177-188`, `src/sessionbuddy/platform/storage/scanner.py:18` — **CONFIRMED**

`env.dev` — deployed by `npm run worker:deploy:dev` to a public `workers.dev` URL — sets `APP_ENV: "development"`, `MALWARE_SCAN_MODE: "disabled"`, `SCANNER_URL: ""`. The bypass predicate accepts `development` alongside `local`:

```python
return app_env in {"local", "development"} and mode == "disabled"
```

*(verified: **six** upload paths bypass, not four — `access.py:1125, 2316, 2446, 2539`, `cfp/router.py:1634`, `speaker_operations/router.py:1834`.)* Anyone who self-registers through a published CFP on that deployment can upload a 20 MB "PDF" that never touches ClamAV; organizers then download it. AGENTS.md requires demo/bypass behaviour to need an **explicit local** environment — `development` is deployed, not local.

*(verified: `staged_uploads.py:175`'s hardcoded `scan_state='clean'` is **not** an independent defect — `build_staged_claim` only selects rows already marked `status='staged'`, which in production requires a clean verdict.)*

**Fix:** narrow `malware_scan_disabled` to `app_env == "local"`, and bind a real `SCANNER_URL` on `env.dev`.

### 1.4 Session refresh silently re-expands a narrowed role
`src/sessionbuddy/platform/auth/router.py:85-115` + `platform/auth/d1.py:79` — **CONFIRMED**

`refresh_session` mints a new session id but never copies the `session_active_roles` row, and the facts query that feeds the entire policy engine falls back to the account default:

```sql
COALESCE(active.role, default_role.role) AS active_persona
```

A user holding `{organizer (default), speaker}` who deliberately narrows to `speaker` and then refreshes is authorized as **organizer** on every subsequent call. The same fail-open path triggers when the schema trigger `remove_revoked_active_role` deletes the row on revocation — revoking someone's active role promotes their live session to their default one. `docs/rbac-redesign-handoff.md:33` states the opposite invariant ("An active role narrows permissions and never expands them").

*(verified: cannot cross tenants — the fallback is a role the account already holds, and `policy.py:83` still requires an owned/granted resource. Also, `GET /api/v1/auth/session` 403s in this state, so the console breaks visibly.)*

**Fix:** drop the `COALESCE` fallback in `actor_for_session`, and copy the active-role row in the refresh batch.

### 2.3 deserves its own note

This is the single highest-leverage UX fix in the review. Routers write genuinely good copy:

```python
raise HTTPException(409, detail="Applications are closed.")                              # cfp/router.py:233
raise HTTPException(409, detail="Activate the event before publishing its CFP.")         # cfp/router.py:496
raise HTTPException(422, detail="The Call for Proposals must close before the event starts.")
```

…and the handler substitutes a fixed table keyed on status. It's *worse* than doing nothing, because `api_client.js:37-40` prefers the server string over its own friendlier defaults. Every 422 in the product — a bad merge field, an over-long title, a malformed routing rule — collapses to **"The request could not be processed"** with no field named. Fixing one function in `api/app.py` improves error copy across ~43 call sites at once. While you're there: 422 isn't in the `errors` map, so route-raised 422s get code `request_failed` while Pydantic 422s get `validation_failed`.

## 3. Security — remaining findings

**3.1 Unbounded email relay via co-speaker invitations** (`cfp/router.py:148`) — **CONFIRMED.** `_reconcile_co_speakers` filters `invitation_status != 'removed'` when computing what's new, so an add → remove → re-add loop re-queues an email every cycle. The `deterministic_key` uses a **fresh** `new_id()` discarded by the `ON CONFLICT` (`:230`, `:268`), so the `UNIQUE` index never dedupes. No rate limit on the calling route. A self-registered speaker can mail-bomb 10 arbitrary addresses per cycle, indefinitely, from the tenant's verified sender domain, with an attacker-controlled `Subject:`.

**3.2 Public-CFP rate limit keys on a client-chosen header** (`cfp/router.py:2113`) — **CONFIRMED.** `subject = f"{X-Public-Session-ID}:{ip}"`, where the header is only length-checked. Rotate it per request and the 50/min cap never fires. Each request costs ~8 D1 round-trips.

**3.3 Auth rate limits use one composite email+IP key** (`access.py:4164`, `:4280`) — **PARTIALLY CONFIRMED.** `docs/api-security.md` §3.1 requires two *independent* limits. *(verified: the password path is separately protected by a per-`user_id` exponential lockout at `access.py:4308-4330` that IP rotation can't defeat — so the real exposure is the magic-link endpoint, where N source IPs give 10·N sign-in emails/minute to one victim address.)*

**3.4 Presigned R2 PUTs don't bind size; speaker uploads have no quota or purge** (`sigv4.py:38`, `speaker_operations/router.py:1520`) — **CONFIRMED.** `SignedHeaders = "content-type;host"` omits `content-length`, and `authorize_speaker_upload` has neither a rate limit nor a quota (unlike the CFP staged path, which has both). `entry.py:32-72` purges only `cfp_staged_assets` — nothing sweeps `pending_upload` rows. An accepted speaker can loop authorize → PUT 5 GiB → never complete, and the objects persist forever.

**3.5 Sign-in tokens in the URL + full-fidelity invocation logging** (`access.py:4236`, `wrangler.jsonc:10`) — **CONFIRMED.** *(verified: `observability` is a top-level inheritable key that `env.dev` never overrides, so `invocation_logs: true, head_sampling_rate: 1` applies to deployed environments.)* Cloudflare Workers Logs retain the full URL, so live sign-in tokens are readable by anyone with dashboard log access for the 15-minute challenge lifetime.

**3.6 Production accepts the non-`__Host-` cookie name; logout doesn't clear it** (`http.py:92`, `router.py:169`) — **PARTIALLY CONFIRMED.** *(verified: impact is narrower than first stated — `__Host-session` is read first in the `or` chain, and logout revokes server-side, so the stale name carries a dead token. The residual risk is session fixation: because `sessionbuddy-local` lacks `__Host-` and `Secure`, a subdomain or network attacker could plant a valid attacker-owned session on a not-yet-signed-in victim.)*

**3.7 Co-speaker acceptance reactivates revoked memberships** (`cfp/router.py:1018`) — **PARTIALLY CONFIRMED.** *(verified: no privilege escalation — the org conflict clause demotes a revoked admin to `member`, and the event conflict key binds `role='speaker'` literally. A revoked speaker can be brought back to `active` via an invitation, but cannot regain authority.)*

**3.8 CSV formula-injection guard misses tab and CR prefixes** (`evaluation/router.py:2009`) — **CONFIRMED.** Prefix tuple is `("=", "+", "-", "@")`; a title starting with `\t=HYPERLINK(...)` evaluates in Excel/LibreOffice after leading-whitespace stripping.

**3.9 No `Strict-Transport-Security`** (`security.py:46`) — **CONFIRMED.** Every other header is present. Documented as deferred, but still absent on a deployed origin.

**3.10 Org `edit` grant satisfies `ORGANIZATION_MANAGE`** (`policy.py:59-68`) — **CONFIRMED.** Only `RESOURCE_ACCESS_MANAGE` requires `MANAGE`; `ORGANIZATION_MANAGE` accepts `EDIT`. So "Can edit" also grants: rename the org, create events, replace branding, enumerate the speaker directory, requeue communications. The console gates all of these on `owner|manage` (`app_shell.js:93-99`, with a comment saying it "mirrors the server's authority model") and hides them — so neither the granting admin nor the grantee can see the discrepancy. *(verified: the EDIT-as-content-authority split is deliberate and tested for `EVENT_MANAGE`; nothing pins `ORGANIZATION_MANAGE` either way. Scope is confined to an explicitly granted resource — no cross-tenant reach.)*

**3.11 `SecurityHeadersMiddleware` overwrites `Cache-Control` on every `/api/` response** (`security.py:59`) — **CONFIRMED.** Runs at `http.response.start`, so it clobbers `public, max-age=60` on the public schedule and `max-age=31536000, immutable` on branding assets. *(verified: `tests/security/test_asgi_middleware_runtime.py:64` **codifies** this — so it's a conflict between two deliberate behaviours, not a regression. Pick one.)*

**3.12 Endpoints with no rate limit at all.** Only 5 `enforce_rate_limit` call sites exist; `docs/api-security.md` §6 names 6 required policies. Sharpest gap: `PUT /api/v1/account/headshot` runs a **synchronous** ClamAV scan per call with no limit — one low-privilege account looping 5 MB uploads saturates the shared scanner, which then fails closed (503) for every upload platform-wide.

### Verified sound — don't regress these

SQL injection (all D1 prepared statements; the 6 f-string sites build `IN (...)` placeholders from `range()` or a closed `Literal` dict) · XSS (1 `innerHTML`, a static literal; all API data via `textContent`; CSP has no `unsafe-inline`/`unsafe-eval`, `object-src 'none'`, `base-uri 'none'`, `frame-ancestors 'none'`) · SSRF (3 outbound fetch sites, all fixed/env-bound; branding copy explicitly refuses external URLs) · password hashing (PBKDF2-SHA256 ×600k, 16-byte salt, separate pepper, `compare_digest`, `needs_rehash`) · token generation (`secrets.token_urlsafe(32)`, only SHA-256 digests persisted) · session lifecycle (idle 12h + absolute 30d, revocation, `authorization_version` staleness, no fixation, password change revokes all sessions) · CSRF primitive itself (exact Origin + non-simple content type + session-bound HMAC token) · scanner protocol (HMAC both directions, independent body-hash recomputation, ±5min window, fail-closed everywhere, non-root container) · download grants (single-use atomic `UPDATE…RETURNING`, 1–300s TTL, principal-bound, `scan_state` re-checked at issue *and* consumption) · idempotency scoping (`UNIQUE(principal_key, route_key, key_hash)` with `principal_key` always the authenticated user) · logging (route templates only; audit metadata redactor rejects `token`/`cookie`/`secret`/`password`/`url`/`email` keys) · `APP_ENV` fail-closed defaults throughout · **`console/embedded_assets.py` is byte-identical to all 68 source assets** (independently re-verified by regenerating and diffing each constant) · Engine Room public models carry no tenant/identity/submission data, as AGENTS.md requires · **final evaluation decisions are genuinely immutable** — no update path exists anywhere for `submission_decisions`, and a `final` evaluation can't be re-saved.

## 4. UX — the flow-breaking findings

**4.1 The "Edit CFP" button is unreachable after publishing** (`admin_programs.html:19-52`, `admin_programs.js:1074-1078`) — **CONFIRMED, definitively.** The share card containing `#edit-cfp` lives inside `<dialog id="cfp-share-dialog">`. `showModal()` is never called on it anywhere in the repo; no CSS overrides the UA's `dialog:not([open]) { display: none }`. The publish-success path sets `state.editing = false` and re-renders, which hides the form builder and notification settings. *(verified: not a fully blank page — the live-URL bar, Copy, Edit URL, and Preview survive.)* The organizer publishes, the entire editor vanishes, and the only recovery is a full page reload (`restoreSession()` sets `state.editing = true` on load). "Discard changes" does the same thing. The existing test asserts the markup exists but never that it's *shown*, so this passes CI.

**4.2 There is no in-product way to discover an open CFP** (`app_shell.js:618-645`) — **CONFIRMED.** A complete, working public-events renderer — with empty and failure states — targets `[data-public-events]`, an attribute that appears in **zero** HTML files. `landing.html`'s only two event links point at external `ai.engineer` marketing URLs. `/api/v1/public/events` has no in-product caller. Every CFP link must be circulated out of band.

**4.3 The nav step named "Publish" cannot publish anything** (`app_shell.js:325`, `event_workspace.js`) — **CONFIRMED.** The guided rail's final step opens a 64-line page containing an iframe-embed generator and an Accelevents token form. No publish control, no agenda status, no link to `/agenda` where publishing actually lives. Its "Open public view" button, on an unpublished agenda, lands on "The organizer has not published the schedule yet" — with no path back.

**4.4 Editing a live CFP has no draft protection and no 401 recovery** (`admin_programs.js:938-943`, `:1004`) — **CONFIRMED.** `queueLocalDraft()` is deliberately skipped once a form is published, and the submit catch has no 401 branch. Twenty minutes of rewriting a live CFP + a session expiry = everything gone. *(verified: a `beforeunload` guard does exist at `:1217`, but it doesn't fire on the 401 path since no navigation occurs.)* `events_admin.js:936-938` does this correctly — copy that pattern.

**4.5 Opening an evaluation round pre-checks every eligible submission** (`admin_submissions.js:299-300`) — **CONFIRMED.** No select-all/none control, no selected count, and on failure the message renders in `#status` at the top of the page while the round form sits in a collapsed `<details>` far below. `byId("status").tabIndex = -1` was set at `:13` for exactly this — and `.focus()` is never called. *(verified: the two `.focus?.()` calls at `:392` target a `<div>` and a `<tbody>`, both no-ops.)* An organizer with 200 proposals who opens the form to assign a curated subset creates 200 assignments and 200 reviewer emails in one click.

**4.6 Speakers see that a message was sent but can never read it** (`speaker_operations/router.py:721-727`) — **CONFIRMED.** `SpeakerNotificationView` carries `{id, subject, delivered_at_ms}` and the query selects only those three columns; no route anywhere returns `html_body` to a speaker. Organizers compose 10,000-character messages with deadlines and portal links. A speaker who lost the email sees "Deadline reminder · 3 Mar 2026, 09:00" and has no way to read it and no resend.

**4.7 The public proposal form has no autosave and no unsaved-changes guard** (`public_cfp.js`) — **CONFIRMED.** No `beforeunload`, and `saveBrowserDraft` fires only on explicit actions. The page's own copy promises "Take your time. You can save a draft." This is the highest-stakes form in the product and the least protected.

**4.8 Public CFP inputs allow 500 chars where the server caps at 200** (`public_cfp.js:198-202` vs `cfp/models.py:322-325`) — **CONFIRMED.** `speaker_name` and `proposal_title` are capped at 200 server-side, `speaker_email` at 320 *(verified: the email field is also mismatched — the original claim missed it)*. Counters are installed on `textarea[maxlength]` only. So a 240-char title types fine, passes client validation, and fails with "A required answer is missing or invalid. Go back and review every required field" — no field named. The same field is capped at 200, 300, and 500 in three different pages.

**4.9 Unconfirmed destructive actions.** Archiving a room, track, or label is one click with no confirmation, no consequence copy, and no restore path (`agenda.js:199-233`, `:718-768`) — *(verified: the API **can** restore via `PATCH {status:"active"}`; the trap is that list endpoints filter `status='active'`, so the id becomes undiscoverable from the product)*. Archiving an **active event** is a `<select>` change with no confirmation (`events_admin.js:891`). Bulk speaker sends have no recipient confirmation. Declining a co-speaker invitation is one irreversible tap. Contrast the excellent patterns already in the codebase: the agenda publish dialog counts sessions going public, and `access_admin.html:23-38`'s ownership transfer names the incoming owner, states what happens to the outgoing one, and lists what does *not* change.

**4.10 Embed settings are localStorage-only but labelled as a switch** (`event_workspace.js:30-45`) — **CONFIRMED.** No API call persists them, and `/embeds/events/{id}/schedule` serves unconditionally. Unticking "Embed enabled" does nothing; the embed keeps serving. A colleague on another machine sees defaults.

**4.11 Vocabulary drift.** The same object is a *proposal*, a *submission*, and a *session* — often on one screen. `admin_submissions.html` has `<h1>Submissions</h1>` over `<h2>Proposal inbox</h2>` with a "Read proposal" button and success copy saying "N submissions added". The reviewer dashboard says "decide which **sessions** move forward" above "**Submission** results" rendering `proposal_title`. It's worst at the decision moment, where the wrong mental model leads to an irreversible accept/reject.

**4.12 Timezone presentation is inconsistent and mostly unlabelled.** `speaker_portal.js` renders in the event zone but labels it on only one of four call sites; `speaker_content.js:129`, `speaker_messages.js:85`, and `co_speaker_invitation.js:43` silently switch to the *viewer's* zone. A Berlin-based speaker at a San Francisco event reads "Mar 12, 2026, 9:00 AM" with no way to know which 9:00 that is. Two pages get it right and should be the model: `schedule.js:100` ("Times shown in {zone}") and `main.tsx:457` ("(your local time)").

**4.13 No unsubscribe or preferences mechanism on any outbound email** (`communications/rendering.py`). `ALLOWED_VARIABLES` has no such token and no `List-Unsubscribe` header is set. A speaker on three rosters has no opt-out short of replying to an optional reply-to address.

**4.14 Accessibility.** Four organizer pages share `<title>Speakers · SessionBuddy</title>` and *(verified: all **four**, not three)* share `<h1>Speakers</h1>` — heading navigation can't distinguish the directory, onboarding tracker, file collector, and mail composer. `events_admin` declares `role="table"` with an `aria-hidden` header row and appends the empty state as a `<p>` child of the table (commonly pruned from the a11y tree, so "No events yet — create your first event" is never announced). The CFP rich-text editor is a `contenteditable` div inside a `<label>`, which gives it no accessible name; link insertion uses a native `prompt()`. Agenda drop-target groups are `tabIndex=0` with no keyboard action, and an empty board has no drop target at all — on the first-run moment, "drag a session into a group" is impossible. `class="muted"` is used on 9 elements and defined in **zero** stylesheets, so text meant to be de-emphasised renders at full contrast.

### UX patterns worth preserving

`api_client.js` is genuinely good — one typed error, per-status copy, request-ID references, auto-installed character counters and required markers via `MutationObserver`. `speaker_portal.js`'s upload form has a real `<progress>`, pre-upload checksum, and resumable completion after a scanner outage. `events_admin.js` correctly rejects DST-gap times, autosaves to `sessionStorage`, and restores after a 401. The agenda publish dialog and the ownership-transfer panel are models of destructive-action design.

## 5. UI consistency — highlights

Full inventories (409 hex values, 43 gap values, 30 radius values, 11 breakpoints, per-page shell status) are in the detailed findings; the load-bearing items:

- **No token layer.** Six competing `:root` sets. `#6d4aff` is spelled `--blue`, `--sb-violet`, and `--speaker-violet` in three files that load *together*. `--blue` means violet in `product.css` and blue in `reviews.css`. `speaker.css` `@import`s `product.css` and then declares `--speaker-ink: #182235` next to the imported `--ink: #182230` — two body-text tokens one unit of blue apart, live simultaneously.
- **Four primary buttons.** Purple gradient (`product.css`), indigo (`landing`/`error_page`), blue 600-weight (`reviews`), blue with `cursor: wait` on disabled (`admin_onboarding`). A signed-in user hits all four in one session.
- **`admin_onboarding` doesn't load `product.css`** — one tab of a four-tab hub swaps the entire visual system, while still carrying product-only class hooks that now resolve to nothing.
- **Six renderings of the same status.** "Accepted" appears as `accepted`, `ACCEPTED`, and `Accepted` across pages, in four different greens.
- **Five list primitives for five admin list pages** — `<table>`, `<table>` + a *duplicate* `<ul>` DOM tree, `div[role=table]`, card grid, `<ul>`. One of them already solves the responsive problem in pure CSS; the others don't.
- **Five focus rings**, two of them live on the same page (`agenda_admin` renders amber view-switcher rings and blue rings on everything else). `admin_onboarding`'s selector omits `input` and `textarea`, so its filter fields have **no visible focus ring**.
- **Version-string drift** — `product.css?v=57` on 18 pages, `?v=58` on 3; `app-shell.js?v=14` on `/reviews` vs `?v=22–24` elsewhere. *(verified: these assets ship with **no** `Cache-Control` header at all — the original claim cited the wrong route; heuristic caching, not a 24h pin. The drift is real, the stated consequence was overstated.)*
- **Seven hand-rolled date formatters** under six names with divergent null/failure handling, plus nine call sites that bypass the event timezone entirely.
- **Dead selectors** from page rewrites: `.event-overview-heading`, and a full navy-header block in `admin_onboarding.css:7-12` and `agenda.css:22-32` for a header that no longer exists.
